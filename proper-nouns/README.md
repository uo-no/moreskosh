# 固有名詞の同定データ（キュー #412・ドラフト）

固有名詞には語義を出さず、「同定」（その名前が誰・何を指すかの一行説明）を出す。そのためのデータで、NGSD の語義とは別の層として作る。表示（語ページ・PDF）への組み込みはデータ確定後の別アクション。**ここにあるものはすべてドラフト（未確定）**で、本番データ・表示には何も反映していない。

## ファイル

| パス | 内容 |
| --- | --- |
| `target-list.json` | 対象リスト。新約本文（`public/bible_data/nt`、全260章）で `type` が `proper` のトークンを lemmaId 単位で数えた 540 レンマ・4,626 トークン。各項目は `lemmaId`・`lemma`（最も多い表記）・`forms`（表記が2つ以上あるときの内訳）・`strong`・`total`・`band`（頻度帯） |
| `drafts/<Strong>.json` | パイロット（頻度20以上・33レンマ）の同定ドラフト。1レンマ＝1ファイル |
| `tools/build-target-list.cjs` | `target-list.json` を作る。仕様の実測値（540・4,626、頻度帯ごとの内訳）と一致しなければ書かずに止まる。`--check` で再生成結果との一致を確認 |
| `tools/pilot-judgments.cjs` | 同定の判断表（対象の文言・割り当てる箇所・注記・迷う箇所）。人が書く正本 |
| `tools/build-pilot-drafts.cjs` | 判断表を本文のトークンに当てて `drafts/` を書く。`--check` で各ドラフトの count 合計＝total を機械確認 |

```sh
node proper-nouns/tools/build-target-list.cjs          # 対象リスト
node proper-nouns/tools/build-pilot-drafts.cjs         # ドラフト生成（割り当ての検査つき）
node proper-nouns/tools/build-pilot-drafts.cjs --check # count 合計＝total の確認
```

## ドラフトの形式

```jsonc
{
  "lemmaId": "grc:G2385",
  "lemma": "Ἰάκωβος",
  "forms": [{ "form": "…", "count": 0 }],   // 表記が2つ以上ある lemmaId のみ
  "strong": "G2385",
  "total": 42,                               // この lemmaId のトークン総数
  "status": "draft",
  "identifications": [                       // 1階層目：指す人物・対象ごと（同一人物は1つにまとめる）。語義とは呼ばない
    { "id": "3", "label_ja": "イエスの兄弟ヤコブ（エルサレム教会の指導者）", "count": 11, "refs": ["MAT 13:55", "…"],
      "roles": [                             // 2階層目（任意）：同じ人物の役割ごとの内訳。2つ以上のときだけ置く
        { "id": "3.1", "label_ja": "イエスの兄弟として", "count": 3, "refs": ["MAT 13:55", "MRK 6:3", "GAL 1:19"] },
        { "id": "3.2", "label_ja": "エルサレム教会の指導者として", "count": 5, "refs": ["ACT 12:17", "…"] }
      ],
      "variants": {                          // 言語ごとの表記のバリエーション。本文で確認できた形だけ（推測で埋めない）
        "ja": [
          { "form": "ヤコブ",                // 表示に使うのは form だけ（例：「パリサイ人、パリサイ派」と形を並べる）
            "sources": [                     // 裏取り用（表示しない）：その形を確かめた訳と節
              { "source": "口語訳（1955）", "checked_in": "MAT 13:55" },
              { "source": "文語訳（1917年改訳）", "checked_in": "MAT 13:55" } ] }
        ] } }
  ],
  "note_ja": "…",                            // 任意：称号の来歴、別 lemmaId が同じ対象を指すこと、まとめ方の根拠 など
  "flagged": [                               // 任意：振り分けに迷う箇所（確定はポポの一次判定とユーザーの決定）
    { "refs": ["1CO 15:7"], "assigned_to": ["3.3"], "reason_ja": "…" }
  ]
}
```

- `count` はトークン数、`refs` は節単位（重複なし・本文順）。同じ節に同じ名前が2回あれば `count` は2、`refs` は1件。
- `identifications` は人物（場所・集団なども含む対象）の単位。同じ人物が本文で別の役割で現れるときは1つにまとめ、`roles` に役割ごとの `count`・`refs` を持つ。人物の `count`・`refs` は役割の合計（和集合）で、`roles` の `count` 合計 ＝ 人物の `count`。役割が1つだけの人物は `roles` を置かない。
- 同一人物かどうか自体に議論があるもの（黙示録の記者ヨハネとゼベダイの子ヨハネ、小ヤコブとアルパヨの子ヤコブ など）はまとめず、別の対象のまま `label_ja` に「…と同じ人物かには議論がある」と書く。
- 指す対象が一つの名前は `identifications` が1要素で、`count` ＝ `total`。複数に分かれる名前は `count` の合計 ＝ `total`。
- `flagged` の箇所も、いったんどこかの対象に割り当ててある（`assigned_to`。役割に入っていれば `"3.3"` のように役割の id）。`refs` が `["（全体）"]` のものは、レンマ全体の分け方そのものの判断。
- `variants` は同定ごとの表記のバリエーション（言語コードごと）。表示は `form` だけを並べ、どの訳の形かは出さない。`sources` は裏取り用に、その形を確かめた訳（`source`）と節（`checked_in`）を保持する。確かめられない形は載せない（空配列もありうる）。並びは、確かめた訳の多い形が先。
  - 確かめ方：その同定に割り当てた節の訳文に、候補の形（`tools/renderings-ja.cjs`）が出るかを見る。前後がカタカナで続く一致は数えない（「ユダ」が「ユダヤ」に当たらないように）。長い候補に含まれる短い候補は数えない（「パリサイ派」の中の「パリサイ」）。同じ節に同じ名前の別の同定があるときは、関係する候補のうち1種類の形しか出ず、その出現回数が節内のトークン数以上のとき（どのトークンもその形で訳されている）に限って使う。
  - 確認元は口語訳（`public/translations/JA1955`）と文語訳（`public/translations/BUN`、1917年改訳）。パイロットの JA 表記はこの2訳で確定する（2026-11-27 ユーザー決定）。新改訳2017・新共同訳の表記はこの環境では確認しない（公開前の裏取りは別途）。
  - 載せるのは名前の形だけ。称号の訳語（例：Καῖσαρ を「皇帝」と訳す箇所）は表記に含めず、称号であることは同定文（`label_ja`）で述べる（2026-11-27 ユーザー決定）。
  - 確かめられなかった同定：イエス・バラバ（マタイ27:16 の訳文はどちらも「バラバ」のみで、Ἰησοῦν にあたる形が無い）。
- 別の lemmaId が同じ対象を指す場合（Ἰερουσαλήμ と Ἱεροσόλυμα、Πέτρος と Σίμων、Ἰωσήφ〈使徒4:36〉と Βαρναβᾶς など）は `note_ja` に書き、項目は統合しない。

## 作り方

- 同定は新約本文そのものに基づいて書いた（各箇所の前後の本文を読んで割り当てた）。Abbott-Smith の固有名詞項目は出発点の仮説としてだけ使った。現代の辞書・事典の文章は写していない。
- 名の表記は bible_data の `japanese`（パウロ・ペテロ・パリサイ人・ピリポ など）にそろえた。
- 判断表の ref は、同じ節に同じ lemmaId が2つ以上あるときは `#n` で何番目かを指定しないとエラーになる（取り違え防止）。全トークンがちょうど一度ずつ割り当てられたことを生成時に検査している。
- 日本語のみ。他言語は JA 確定後の別アクション。
