# NGSD 拡張照合 バッチ2（頻度6〜25回帯・下書き）仕様

## サイズ規則（最優先）
- 作業単位は **1レンマ**。返信・報告は1レンマ単位の進捗が分かる形にし、15レンマをまとめて報告しない。
- 報告はコンパクトに（完了したレンマ名・未解決件数・逸脱のみ。JSON や入力データは貼らない）。
- 途中で切れたら、最後に完了したレンマを名指しして「続き」だけを再開する。完了分は再送しない。

## モデル指定
Sonnet（下書き専用。確定ではない）

## 置き場所
- 材料：ブランチ `work/ngsd-collation-batch01` の `collation/batch-02/`（G*.json 15件＋この SPEC.md）
- 成果物：下書き JSON 15件を `collation/batch-02/drafts/` に置き、同ブランチへ push する（同ブランチへ push できない場合は自ブランチでも可、その旨を結果欄に明記）。PR は作らない

## 材料（パケットの読み方）
- `nt_occurrences`：新約の全用例（箇所・語形・形態・英日グロス・節文）。**語義の対象はこの用例だけ**。
- `lxx` / `fathers`：拡張母集団の総件数・書別内訳・代表例。語義の裏づけ（照合）に使う。
- `abbott_hypothesis_en`：Abbott-Smith の記述。**仮説として扱い、文言を写さない**。用例と合わない場合は用例を優先し、その旨を note に残す。

## 出力形式（1レンマにつき1つの JSON）
```json
{
  "strong": "G93", "lemma": "ἀδικία", "status": "拡張照合・下書き",
  "senses": [
    {"n": 1, "label_ja": "（訳語候補）", "def_ja": "（語の本質的な意味を記述した定義文）",
     "layers": {"nt": 25, "lxx": "attested|none", "fathers": "attested|none"},
     "note": "（任意：構文情報・層での違い等）"}
  ],
  "assignments": {"MAT 1:1": 1},
  "unresolved": [{"ref": "ROM 1:1", "reason": "（判断が割れる理由）"}],
  "layer_notes": "（任意：LXX・教父にだけ現れる用法があればここに記録。語義にはしない）"
}
```

## 規則
1. 語義は新約の用例から立てる。LXX・教父の用例は裏づけ専用で、新約に無い用法は語義にせず `layer_notes` に記録する。
2. 新約の全用例を必ずどれかの語義に割り当てる。割れないものは無理に寄せず `unresolved` に理由つきで残す。語形が別のレンマのものと疑われる場合も、寄せずに `unresolved` へ（理由に疑いの根拠を書く）。
3. 同じ節に同じ語が複数回ある場合は、assignments のキーに `MAT 7:17#1` のように連番を付けて区別する（パケットの出現順）。
4. `label_ja` は訳語候補、`def_ja` は本質定義の二層に分ける（既存 NGSD の体裁に合わせる）。
5. 各語義の `layers.nt` は、その語義への実際の割当て件数と一致させること（最後に数え直す）。lxx／fathers は代表例で確認できた場合のみ "attested"（総件数だけで判断しない）。
6. 状態は「拡張照合・下書き」。final と書かない。
7. 固有名詞は対象外（このバッチには含まれていない）。
