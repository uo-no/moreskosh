# 検索パターン全検証（キュー #418）

`/pdf` の入力は Greekn（`/search`）の URL そのもの。箇所 URL の小辞典（#411〜#417）に続き、残りの検索パターンについて「その URL が小辞典として何を意味するか」を、検索の実装（`public/search-tool.html`）と実データから確かめ、代表サンプルを作った。サンプル提示用で、`/pdf` の実装でも本番反映でもない。

## 作り方

1. **ヒット集合は検索画面そのものから取る**：`scripts/search-hits-harness.cjs` が、本番と同じ `search-tool.html` をローカルの静的サーバー（`/search`・`/ja/search/…` を `search-tool.html` に向ける。本番の `_redirects` と同じ）で開き、ヘッドレス Chromium で検索を確定させてから内部状態を読む（通常の検索は `_allMergedResults`、統語の構文タイプは `_synFiltered`、逆引きは `_revCands`）。実装を写し直していない。
2. **独立の検算**：検索画面とは別に、本文データ（`public/bible_data/nt`）から各パターンのヒット集合を数え直し、9 件すべて（下表の 9 パターン＋G4412）で集合が完全に一致した。
3. **小辞典**：`scripts/build-ngsd-pdf-sample.cjs --hits <hits.json>`（#418 で追加したモード。範囲モードの出力は #417 とバイト単位で同一のまま）。組版・根拠タグ・同定・リンク形式は #417 の確定形。ヒットは新約分のみ使う（LXX のヒットは除外し、件数を冒頭に注記）。
4. 一括実行：`node scripts/build-pattern-samples.cjs --harness docs/samples/ngsd-pdf/patterns/harness-raw.json`（`--harness` を省くと検索画面からの取り出しからやり直す）。`hits.json` に各パターンの件数・ページ数。

暫定ルール（キュー #418 の指示）：項目＝ヒットしたトークンの見出し語、並び＝ヒット集合内の初出順（新約の書・章・節の順）、中心の語義＝ヒットに割り当てられた語義を全文（ヒットの多い順）、ヒットしていない語義は1行。単一の見出し語に解決されるパターン（2・3・5）は全語義を全文。

## パターンごとの URL 形式とヒット集合

| # | パターン | URL 形式 | ヒット集合の定義（実装） | 存在 |
| --- | --- | --- | --- | --- |
| 1 | 日本語の単語検索 | `/ja/search/<日本語>` | トークンの日本語グロス（`bible_data` の `japanese`、無ければ `gloss`）に、その文字列を**部分一致**で含むトークン（事前生成の部分文字列索引。部分文字列は 8 字まで）。概念（`search-concepts.json`）に登録された語なら、その概念の Term 群のヒットを和集合で足す。別に「逆引き」タブ（NGSD の本体 482 語の語義ラベルからの照合。トークン集合ではなく語義の一覧）が出ることがある | あり |
| 2 | 見出し語 | `/ja/search/<ギリシャ語>` | `lemma` をアクセント・気息・大文字を除いて正規化し、一致するトークン（`lemmaIndex`）。NGSD の見出し語の束ね（例 εἰμί）ではなく lemma の綴りで引く | あり |
| 3 | 活用形 | `/ja/search/<活用形>` | 1語のギリシャ語が lemma として無く、表面形として有るとき、その形を持つトークンの lemma を候補にする。候補1つ→その lemma で 2 と同じ検索（ヒット集合は 2 と同一。入力した形のトークンに「語形」の印が付くだけ）。候補が複数→選択画面になりヒットは無い | あり |
| 4 | 形モード | `/ja/search/"<形>"`（半角二重引用符） | 表面形を正規化（アクセント・気息除去、語末 ς→σ、小文字化）して完全一致するトークン。lemma 展開・概念展開をしない。形態タブのときだけ | あり |
| 5 | ストロング番号 | `/ja/search/G<番号>`（`G` は省略可） | `strong` の数字部分が一致するトークン（例 G4412 と G4412a も同じ番号として当たる） | あり |
| 6 | 形態検索 | `/ja/search/<語>?pos=…&tense=…&mood=…&voice=…&case=…&number=…&gender=…`（値はカンマ区切り。軸の先頭に `-` で、その軸の否定） | 語の検索結果（1〜5 のいずれか）を、形態タグで後から絞る。軸の中は OR、軸どうしは AND、`-` はその軸の「以外」。**語なしの形態検索は無い**（検索語が空なら検索しない）。関係・統語タブでは形態の絞り込みは適用されない | あり（語の検索への絞り込みとして） |
| 7a | 関係（近接・フレーズ） | `/ja/search/<語1> <語2>`（実行後 `?tab=rel` が付く。距離は `?dist=N`、既定 5） | ①連続フレーズ（語1 語2 が隣接）の両トークン ＋ ②近接：語1 のトークンのうち、前後 N 語（globalIdx の差。**節や書をまたぐ**）に語2 があるもの。②では語2 のトークンはヒットに入らない（非対称）。1語＋`?tab=rel` は通常の検索と同じヒット（共起語はチップとして別に出るだけ） | あり |
| 7b | 統語（構文タイプ） | `/ja/search?tab=syn&syntax_id=<タイプ>` | 構文解析器（SyntaxAnalyzer）をブラウザ内で新約全体に走らせ、そのタイプが第1候補で確信度 30% 以上のトークン（現行パネルの既定）。書物・確信度・スタブのフィルタは URL に載らない。語＋`?tab=syn` は「その語が担う構文タイプの一覧」で、ヒット集合は通常の検索と同じ | あり |
| 7c | 役割（主語・目的語など）の絞り込み | — | 検索の実装に、トークンの役割（`role`）で絞る経路は無い | **現行では存在しない** |
| 8 | Not検索（語と語の除外） | `/ja/search/<語>?excl=<見出し語>:<語>,…` | 共起チップの「除外」。検索結果のうち、指定した見出し語のトークンがある節で、指定した語（**表面形の完全一致**）を含む節を落とす。単位は節。形態の「以外」（6）とは別物 | あり（共起の除外として） |

## ヒットモードで #417 の組版から変えた点

- 冒頭：「範囲」の代わりに「検索」（URL）と「ヒット」（新約の語数。LXX 除外の注記）。表題は「「…」の検索から」。
- 用語：「この箇所の形」→「ヒットした形」、凡例の「この箇所で使われた語義・この箇所の用例」→「ヒットした用例で使われた語義・ヒットした用例」。用例行の箇所は書名つき（例「マタイ 21:19」）。
- 中心の語義の順：ヒットの多い順（範囲モードは番号順のまま）。全語義モードは番号順。
- 段組：1項目・1語義が1段に収まらないことがあるため、項目と語義のまとまりは段をまたげるようにした（語義名の直後と用例1行の途中は分けない）。範囲モードは従来どおり項目を分けない。

## 暫定ルールで無理があった点・判断が要る点

1. **日本語検索（1）は「意味」ではなくトークンの日本語グロスの部分一致**：「いちじく」は συκῆ・σῦκον に加え、συκομορέα（いちじく桑）・ὄλυνθος（青いいちじく）も拾う。一方「羊飼い」は本体のヒットが 0 で、逆引きタブにだけ ποιμήν の語義が出る（逆引きは NGSD 本体 482 語の語義ラベルからの照合で、トークン集合ではない）。日本語 URL の小辞典を「グロスの部分一致のトークン」で作るか、「逆引きの語義」で作るか、両方か。
2. **単一の見出し語に解決されるパターン（5）の前提が崩れる番号がある**：ストロング番号は数字部分の一致なので、G4412 は NGSD の 3 見出し語にまたがる。逆に見出し語検索（2）は lemma の綴りで引くので、G1543 の二つの綴り（ἑκατοντάρχης 17・ἑκατόνταρχος 3）は見出し語検索では片方しか当たらない。5 を「全語義を全文」にするのは、見出し語が1つのときだけにするか。
3. **活用形（3）の小辞典は見出し語（2）と同じになる**：解決後のヒット集合は 2 と同一で、入力した形を示すのは画面上の印だけ。PDF で入力した形の用例を区別して示すか。候補が複数の形（φιλῶν）は URL がヒット集合を持たない（選択画面）ので、`/pdf` で受け付けないか、候補ごとに作るか。
4. **形態検索（6）は語なしでは成立しない**：「アオリスト命令法の全用例」のような語なしの形態 URL は今の検索に無い。小辞典の入力にしたいなら検索側の機能追加になる。
5. **関係タブ（7a）のヒットは非対称で、節をまたぐ**：近接のヒットは語1 のトークンだけで、語2 は連続フレーズのときしか入らない（サンプルの ἐλπίς はⅠコリント13:13 のフレーズ分だけ）。窓は globalIdx の差なので節・章・書の境目をまたぐ。小辞典で語2 も項目に立てるか、窓を節内に限るか。
6. **統語（7b）は解析器の候補で、URL がフィルタを再現しない**：ヒットは確信度つきの解析結果（第1候補・30% 以上）で、確信度・書物の絞り込みは URL に載らない。タイプによっては NGSD 未収録語だけになる（例：グランビル・シャープ構文 83 件はすべて ὁ、行為者与格 12 件はすべて ὅς）。L-0（推論を断定として出さない）の観点で、解析結果を小辞典の項目集合にしてよいか、確信度を冊子に出すか。
7. **役割での絞り込み（7c）は存在しない**：作っていない。
8. **Not（8）は「語と語の除外」ではあるが、共起チップの除外として実装されている**：除外語は表面形の完全一致（アクセント込み）で、見出し語単位ではない（例：ἀπόστολος を除外しても ἀπόστολοι の節は残る）。`/pdf` の入力としてこの意味のまま受けるか。
9. **LXX**：検索のヒットには LXX が入るが、小辞典は新約のみ（冒頭に除外数を注記）。LXX の lemma は CATSS 式（例「ὁρίζω ἀπο」）なので、見出し語検索ではほぼ当たらず、ストロング番号・表面形でだけ当たる。除外の注記をこのまま出すか。
10. **大きな検索**：今回は数十語以内のクエリを選んだ。ヒットが数百〜数千のパターン（例：καλέω 単独 148 トークン、構文タイプの命令的分詞 1,321 件）の上限・分冊の扱いは未決（#411 の生成上限の議論と同じ）。
11. **URL の付随パラメータ**：`?lemma_tab=<lemma>`（結果を1つの lemma に絞る表示タブ）、`?dist=N`（近接の距離）を `/pdf` がヒット集合の定義に含めるか。今回のサンプルはどちらも既定（なし／5）。
